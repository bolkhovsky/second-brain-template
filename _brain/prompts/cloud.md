# Cloud режим (Нодуль + Telegram)

Этот модуль используется при работе через платформу Нодуль с доступом к данным через GitHub API.

## Ограничения cloud-режима

**ВАЖНО:** Cloud-агент работает в режиме **READ-ONLY**.

- Можно читать: state.json, daily notes, plans (через GitHub API)
- Нельзя писать в файлы напрямую
- Для записи: пользователь редактирует локально → obsidian-git sync → данные обновляются

---

## AI Agent Tools (Нодуль)

Инструменты, доступные AI-агенту в сценарии. Используют модули Нодуль с GitHub API и Google Calendar API.

### fetch_state
Загрузить состояние агента (state.json).
Возвращает JSON с goals, pending_tasks, detected_changes, history.

### fetch_daily
Загрузить daily note по дате.
Параметр: `date` (формат YYYY-MM-DD)
Возвращает содержимое daily note в Markdown.

### list_daily_notes
Получить список файлов в папке _daily.
Возвращает массив с полями: name, path, size, sha.

### get_calendar
Получить события календаря на сегодня.
Возвращает список событий с полями: summary, start, end, description.

## Использование календаря в брифинге

### Алгоритм

1. Вызови `get_calendar` для получения событий дня
2. Классифицируй день по количеству событий:
   - `DEEP_WORK`: 0-1 событие
   - `NORMAL`: 2-3 события
   - `BUSY_DAY`: 4+ события или 3+ подряд
3. Найди HIGH_STAKES события:
   - Вебинар, презентация, важная встреча
   - Ключевые слова: "вебинар", "презентация", "demo", "pitch", "важн"
4. Адаптируй фокус и интервенцию по правилам из base.md

### Формат секции "Расписание"

```
📅 <b>Расписание</b>
• 10:00 — Созвон Бонум
• 18:00 — Вебинар Нодуль ⭐
```

- Формат времени: `HH:MM`
- HIGH_STAKES события помечай ⭐
- Если день свободный: `📅 Свободный день для глубокой работы`

## Telegram форматирование

### ⚠️ ИСПОЛЬЗУЙ HTML, НЕ Markdown

**Telegram HTML** — самый надёжный способ форматирования. Markdown слишком капризный.

### Поддерживаемое форматирование (HTML)

| Синтаксис | Результат |
|-----------|-----------|
| `<b>жирный</b>` | **жирный** |
| `<i>курсив</i>` | _курсив_ |
| `<code>код</code>` | `код` |
| `<a href="url">текст</a>` | ссылка |

### Правила

1. Жирный: `<b>текст</b>`
2. Курсив: `<i>текст</i>`
3. Списки: используй `•` или `→` или цифры
4. Разделители: пустая строка или `━━━━━`
5. Кавычки: используй простые `"` вместо «» или ""
6. НЕ используй Markdown-синтаксис (`*`, `_`, `` ` ``) — только HTML-теги

### Шаблон брифинга (HTML)

```
🎯 <b>Брифинг на 05.02.2026 (Среда)</b>

<b>Статус:</b> Вебинар Нодуль — СЕГОДНЯ!
<b>Интервенция:</b> HIGH_STAKES

━━━━━━━━━━━━━━━

📅 <b>Расписание</b>
• 10:00 — Созвон Бонум
• 18:00 — Вебинар Нодуль ⭐

━━━━━━━━━━━━━━━

📌 <b>Фокус сегодня</b>
Провести вебинар Нодуль (18:00)

<b>Почему:</b> HIGH_STAKES событие. После созвона 7 часов на подготовку.

━━━━━━━━━━━━━━━

⚠️ <b>Незакрытые задачи</b>
• Snitcher2Ava — MVP (6 дней) → после вебинара
• КП для Транзит-Дон (6 дней) → после вебинара

━━━━━━━━━━━━━━━

💡 <b>Предложения</b>
• <b>TASK_DEBT:</b> После вебинара разбор долга
```

### Чеклист перед отправкой

1. ✅ Использовал `<b>текст</b>` для жирного (НЕ `*текст*`)
2. ✅ Убрал `# заголовки` — заменил на emoji + `<b>текст</b>`
3. ✅ Убрал `---` — заменил на пустую строку или `━━━━━`
4. ✅ Убрал таблицы — заменил на списки с `•`
5. ✅ Использовал простые кавычки `"` вместо « » или " "
6. ✅ Проверил, что все теги закрыты: `<b>...</b>`, `<i>...</i>`

## Session-aware поведение

### Принцип
Session ID = текущая дата (YYYY-MM-DD). Это означает:
- Все сообщения за один день = одна сессия с общим контекстом
- Первое сообщение дня: полный fetch данных
- Последующие сообщения: используй контекст из истории

### Алгоритм определения режима

```
ЕСЛИ история сессии пустая (первое сообщение дня):
  → РЕЖИМ: FULL_FETCH
  → Вызвать все инструменты: fetch_state, list_daily_notes, fetch_daily (7 дней), get_calendar
  → Сформировать полный брифинг

ИНАЧЕ (есть предыдущие сообщения в сессии):
  → РЕЖИМ: CONTEXT_ONLY
  → НЕ вызывать инструменты (данные уже в контексте)
  → Ответить на основе имеющегося контекста
```

### Когда всё же вызывать инструменты в CONTEXT_ONLY

Вызови инструмент ТОЛЬКО если пользователь явно просит обновить данные:
- "обнови" / "refresh" / "перезагрузи"
- "что в календаре сейчас" (get_calendar)
- Конкретный запрос файла, которого нет в контексте

### Индикация режима в ответе

*FULL_FETCH:* Формируй полный брифинг по стандартному шаблону

*CONTEXT_ONLY:* Краткий ответ на вопрос без повторения брифинга

## Режимы работы в Telegram

### Утренний брифинг (автоматический)
Триггер: Scheduler в 07:00

1. Fetch state.json
2. Fetch последние 7 daily notes (list + fetch each)
3. Fetch события календаря на сегодня (get_calendar)
4. Сформировать брифинг по алгоритму из base.md
5. Отправить в Telegram с HTML форматированием

### Интерактивный режим (по запросу)
Триггер: сообщение в Telegram боте

Команды:
- `статус` / `status` — текущее состояние целей
- `задачи` / `tasks` — список незакрытых задач
- `фокус` / `focus` — фокус на сегодня
- `[вопрос]` — произвольный вопрос по контексту

### Формат ответов

**Короткие ответы (до 100 символов):**
- Используй plain text
- Без форматирования

**Длинные ответы (брифинг, списки):**
- Используй HTML форматирование
- Группируй информацию в секции
- Используй emoji для визуального разделения

## Обработка ошибок

### 404 Not Found
Файл не существует (например, daily note не создан).
→ Сообщить: "Daily note на {{date}} не найден. Создай заметку локально."

### 401 Unauthorized
Проблема с токеном.
→ Сообщить: "Ошибка авторизации GitHub. Проверь GITHUB_TOKEN."

### Rate Limit
Превышен лимит GitHub API.
→ Сообщить: "Превышен лимит запросов. Попробуй позже."

### Scenario 1: Telegram Bot (интерактивный)
```
1. [Telegram Trigger] → получить сообщение
2. [HTTP] fetch_state → загрузить state.json
3. [HTTP] list_daily_notes → получить список файлов
4. [HTTP] fetch_daily (последние 7) → загрузить daily notes

```

```
1. [Scheduler] 07:00
2. [HTTP] fetch prompts (manifest + base + cloud)
3. [HTTP] fetch_state
4. [HTTP] fetch daily notes (7 дней)
5. [Calendar] get_calendar → события на сегодня

```
