# Локальный режим (Claude Code CLI)

Этот модуль используется при работе через Claude Code CLI с прямым доступом к файловой системе.

## Инструменты

Используй стандартные инструменты Claude Code:
- **Read** — чтение файлов
- **Write** — создание файлов
- **Edit** — редактирование файлов
- **Bash** — для операций с файловой системой (ls, cat и т.д.)

## Автообновление markdown планов

При обнаружении изменений в daily notes — обновляй файлы в `_plans/`:

### Что обновлять:
- **Даты** — при reschedule изменить дату + пометка "(обновлено DD.MM)"
- **Чеклисты** — при выполнении задачи `[ ]` → `[x]` + дата "✅ YYYY-MM-DD"
- **Статусы** — при cancel/pause добавить ~~зачёркивание~~ или пометку

### Алгоритм обновления

```
ЕСЛИ detected_changes содержит изменение:
  1. Прочитай соответствующий план из _plans/
  2. Найди упоминание сущности (например, "Вебинар Нодуль")
  3. Обнови дату/статус в тексте плана
  4. Добавь комментарий: "(обновлено DD.MM из daily note)"
  5. Сохрани файл
  6. Запиши в state.json → plan_updates

ЕСЛИ задача выполнена в daily note:
  1. Найди эту задачу в чеклисте плана
  2. Поставь [x] вместо [ ]
  3. Добавь дату выполнения: "✅ YYYY-MM-DD"
```

### Пример обновления

**До (в _plans/...):**
```markdown
- [ ] **Вебинар Нодуль:** Проведён (20.01)
```

**После:**
```markdown
- [ ] **Вебинар Нодуль:** Проведён (29.01) *(перенесён, обновлено 20.01)*
```

### Правила:
- Сохраняй структуру документа
- Не удаляй информацию, добавляй аннотации
- Логируй изменения в `_brain/log.md`
- Записывай историю обновлений в `state.json` → `plan_updates`

## Правила работы с файлами

### DO:
- Читай файл перед редактированием (Read → Edit)
- Сохраняй существующее содержимое при добавлении брифинга
- Используй Edit для точечных изменений
- Валидируй JSON перед записью в state.json

### DON'T:
- Не перезаписывай файлы целиком без необходимости
- Не удаляй существующий контент пользователя
- Не создавай файлы вне разрешённых директорий (_daily/, _brain/, _plans/)
- Не меняй структуру state.json без необходимости

## Режимы работы

### MORNING (утренний брифинг)
1. Прочитай _brain/state.json
2. Прочитай последние 7 daily notes из _daily/
3. Сверь с планом из _plans/
4. Определи интервенцию
5. ВСТАВЬ секцию брифинга В НАЧАЛО файла _daily/YYYY-MM-DD.md
6. Обнови state.json
7. Добавь запись в _brain/log.md

### EVENING (вечерний анализ)
1. Прочитай _daily/YYYY-MM-DD.md — найди секцию рефлексии
2. Оцени: был ли прогресс по главной цели? Выполнен ли фокус?
3. Обнови _brain/state.json: streak или days_without_progress
4. Добавь итог в _brain/log.md
5. НЕ меняй daily note, только читай

### WEEKLY (недельный обзор)
1. Прочитай все daily notes за 7 дней
2. Проанализируй state.json
3. Создай _brain/weekly-YYYY-WNN.md с обзором
4. Обнови patterns в state.json

### ASK (вопрос)
1. Учти state.json, последние daily notes, цели из _plans/
2. Дай конкретный и actionable ответ
